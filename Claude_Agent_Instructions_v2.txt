================================================================================
AGENT INSTRUCTIONS: KiCad BOM Enhancer & Procurement Tool
================================================================================

1. PROJECT OVERVIEW
-------------------
The goal is to develop a Python-based desktop application (PyQt6) that processes 
KiCad CSV BOMs. The tool must enrich component data via distributor APIs, 
manage a local "Part Dictionary" to remember previous assignments, and export 
a professional, formatted Excel spreadsheet.

2. CORE FUNCTIONAL REQUIREMENTS
-------------------------------
*   Smart Grouping Fallback: While KiCad typically groups components, the tool 
    must use Pandas to normalize and consolidate rows by 'Value' and 'Footprint'. 
    It should strip library prefixes (e.g., 'Resistor_SMD:') to ensure 
    consistency.
*   Local Part Dictionary (SQLite): Store mappings of 'Value + Footprint' to 
    'Manufacturer Part Number (MPN)'. If a match is found during import, auto-fill 
    the MPN.
*   API Integration (Libraries): Use dedicated Python libraries (e.g., `digikey-api`) 
    to handle complex auth flows like Digi-Key's OAuth2 automatically. Fetch live data 
    based on MPNs. Priority is given to 'Short Description', stock levels, and 
    distributor-specific PNs.
*   Packaging Logic: Implement a 'Cut Tape' default (95% of cases). Users must 
    be able to toggle to 'Tape & Reel' or 'Digi-Reel/Mouser Reel' via a 
    dropdown in the GUI, which triggers a refreshed API lookup for that specific SKU.
*   Traffic Light Status:
    - GREEN: Exact match found, healthy stock.
    - YELLOW: Low/No stock, or fallback packaging used.
    - RED: Missing MPN or unrecognized component.

3. GUI SPECIFICATIONS (PyQt6)
-----------------------------
*   Main Grid: Editable table showing Reference, Qty, Value, Footprint, Packaging 
    (dropdown), Mfr, MPN, and Stock.
*   Search & Assign Dialog: A modal popup for 'RED' rows. It should allow 
    searching the API, selecting a result, and saving that choice to the 
    Local Dictionary.
*   Settings Menu: UI for managing API credentials (Client IDs, Secrets) and 
    default packaging preferences.
*   Threading (CRITICAL): All API library calls are synchronous and MUST be 
    wrapped in PyQt6 `QThread` workers communicating via `pyqtSignal`. The main 
    GUI thread must never freeze during data fetching.

4. EXCEL EXPORT REQUIREMENTS
----------------------------
The final export must be an Excel (.xlsx) file using the following default columns:
1. Quantity
2. Description (Short version from API)
3. Manufacturer PN
4. Manufacturer
5. Digikey PN
6. Mouser PN
7. LCSC PN
8. Notes

5. TECH STACK & ARCHITECTURE
----------------------------
*   GUI: PyQt6 (with QThread/pyqtSignal for concurrency)
*   Data Handling: Pandas (CSV processing/Grouping)
*   Excel Engine: openpyxl (Formatting, bold headers, auto-width)
*   Database: SQLite (via SQLAlchemy or sqlite3)
*   API Wrappers: `digikey-api` (for Digi-Key OAuth2/search) and `mouser` (or 
    equivalent library/requests for Mouser API).

6. IMPLEMENTATION ROADMAP
-------------------------
PHASE 1: Core Engine. Build the CSV parser with normalization and grouping logic.
PHASE 2: Database Layer. Set up SQLite for the Part Dictionary and mapping logic.
PHASE 3: API & Packaging. Implement the distributor API libraries, ensuring they 
         respect packaging requests (Cut Tape vs. Reel).
PHASE 4: GUI Development. Build the main window, interactive grid, and modal 
         search dialogs. Integrate QThread for all API interactions.
PHASE 5: Formatting & Export. Finalize the openpyxl exporter and finalize polish.
